# C141.13 Runtime Integration

Status: Founder-only runtime integration documentation
Repository: Vivi9max/AIOS-Alpha
Branch: main

## 1. Purpose

C141.13 upgrades the Founder Autonomous Development Loop from a Safety Gate that exists in the repository to a Safety Gate enforced at the actual GitHub write boundary.

Required invariant:
FOUNDER_AUTH
↓
FOUNDER DEVELOPMENT CONTRACT
↓
GITHUB BRIDGE
↓
AUTHORITATIVE READ
↓
C141.13 AUTONOMOUS SAFETY GATE
↓
ALLOW / DENY
↓
WRITE
↓
COMMIT
↓
READBACK
↓
CONTENT MATCH
↓
VERIFIED
The Safety Gate MUST execute before writeGitHubFile().

## 2. Runtime Boundary

Primary runtime dispatcher:

`lib/github/task-dispatch.ts`

C141.13 runtime adapter:

`lib/github/c141.13-safety-runtime.ts`

Founder dispatch route:

`app/api/founder/github-dispatch/route.ts`

The runtime adapter provides the hard pre‑write interception point.

## 3. Mandatory Pre‑Write State

Before an autonomous write, the runtime MUST read the target file from the authoritative GitHub branch.

Required state:

* repository
* branch
* target path
* existing file SHA when available
* existing file content
* proposed content
* Founder Development Contract

If authoritative READ fails, autonomous WRITE MUST be blocked.

Expected failure code:

`GITHUB_EXISTING_CONTENT_READ_FAILED`

## 4. Safety Gate Enforcement

The Safety Gate MUST be evaluated using the real pre‑write state and proposed change.

Conceptual runtime boundary:

```typescript
const safety = await assertC14113AutonomousSafetyBeforeWrite({
  request,
  repository,
  branch,
  path,
  existingFileSha,
  existingContent,
  contract,
});
if (!safety.allowed) {
  return {
    success: false,
    code: "AUTONOMOUS_SAFETY_GATE_DENIED",
    error: safety.reason,
  };
}
No writeGitHubFile() call may occur before this check passes.

5. Hard‑Deny Invariant

Autonomous writing MUST fail closed for:

1. Founder Contract rejection.

2. Unauthorized repository.

3. Unauthorized branch.

4. Unsafe path.

5. Protected configuration path.

6. Failure to establish authoritative pre‑write state.

7. Safety Gate denial.

8. Missing or oversized write content.

9. GitHub authentication failure.

6. Write and Readback

Only after the Safety Gate allows the operation may the runtime call:

writeGitHubFile()

When updating an existing file, the authoritative file SHA MUST be retained for the write.

After writing:

1. obtain the commit SHA;

2. perform a fresh GitHub READ;

3. compare readback content with proposed content;

4. report VERIFIED only when content matches exactly.

Expected successful state:

GITHUB_WRITE_VERIFIED
readbackVerified: true

Readback failures MUST NOT be reported as verified.

Runtime restrictions:

9. Verification Contract

C141.13 is integrated only when all required checks pass:

• [PASS] Founder authorization
• [PASS] Founder contract enforcement
• [PASS] GitHub repository restriction
• [PASS] Main branch restriction
• [PASS] Authoritative pre‑write READ
• [PASS] Safety Gate execution
• [PASS] Safety Gate denial blocks WRITE
• [PASS] Allowed change reaches WRITE
• [PASS] Commit SHA returned
• [PASS] READBACK succeeds
• [PASS] READBACK content matches
• [PASS] Runtime reports VERIFIED
• [PASS] Production build succeeds
• [PASS] Production live test succeeds

A patch file existing in the repository is NOT sufficient evidence of integration.
