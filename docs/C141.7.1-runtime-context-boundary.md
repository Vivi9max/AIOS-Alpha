# C141.7.1 — Runtime Context Boundary

## Objective

Prevent persisted Runtime wrappers and execution instructions from re-entering
the user-facing conversation after refresh, or being forwarded to the AI
provider as historical conversation context.

## Boundary

The runtime has four distinct layers:

1. User Input
2. Runtime Policy / Execution Context
3. Conversation History / Reference Data
4. Persisted Execution State

Runtime Policy is never conversation history.

## Implemented defenses

### Client refresh boundary

`components/chat/ChatPanel.tsx`

- Filters legacy Runtime wrapper messages before restoring the transcript.
- Treats Runtime wrapper text as execution metadata.
- Keeps ordinary user/assistant conversation intact.

### Model conversation boundary

`lib/conversation/builder.ts`

- Filters Runtime wrapper records before constructing provider messages.
- Preserves the trusted system prompt and current user prompt.
- Prevents stale persisted wrappers from becoming model context.

## Expected behavior

A refresh must not cause:

- Runtime system instructions to appear as user messages.
- Historical Runtime wrappers to become current instructions.
- Old execution policies to affect a new request.

A refresh may restore:

- Normal user messages.
- Normal assistant responses.
- Reference profile data.

## Verification

1. Send a request that causes Runtime execution.
2. Confirm the response is normal.
3. Refresh the page.
4. Confirm no Runtime wrapper appears in the transcript.
5. Send an unrelated normal question.
6. Confirm the response follows only the current request and trusted Runtime policy.
7. Repeat after a second refresh.
