
# C170.2 — Dependency Impact Analyzer

Status: Independent implementation candidate
Baseline: C170.1 Repository Intelligence
Runtime: Node.js + repository-installed TypeScript
Dependencies added: None
Schema version: 1

## 1. Purpose

C170.2 analyzes the potential impact of one or more changed repository
files using the verified repository dependency graph produced by C170.1.

It provides:

- Changed-file validation.
- Direct dependency discovery.
- Recursive reverse-dependency traversal.
- Multi-file impact aggregation.
- Likely test candidate discovery.
- Root configuration change detection.
- Conservative static risk classification.
- Explicit fail-closed behavior.

C170.2 is read-only.

## 2. Repository Files

C170.2 adds:

## 3. Public API

The module exports:

analyzeDependencyImpact(root, changedPaths, repositoryIndex)

Arguments:

- root: Git repository root.
- changedPaths: non-empty array of repository-relative tracked paths.
- repositoryIndex: optional C170.1 repository index.

The function creates a fresh C170.1 snapshot for every analysis.

When a repository index is supplied, it validates:

- Schema version.
- HEAD identity.
- Tracked-file inventory.
- Dependency graph equality.

The supplied index is never trusted as the sole source of repository truth.

## 4. Analysis Algorithm

For every changed file:

1. Validate its repository-relative path.
2. Verify that it is tracked.
3. Read its direct dependencies from the C170.1 graph.
4. Traverse reverse dependencies recursively.
5. Prevent repeated traversal through visited-path tracking.
6. Record the minimum discovered dependency depth.
7. Associate the changed-file roots responsible for the impact.
8. Discover likely test candidates.
9. Aggregate results across all changed files.
10. Classify static impact risk.

The reverse traversal follows:

Changed file
    -> Direct importers
    -> Importers of those importers
    -> Further reverse dependencies

The traversal is cycle-safe.

## 6. Risk Classification

Risk levels:

### critical

A change affects one of:

- package.json
- package-lock.json
- tsconfig.json

### high

A change includes a root configuration file, at least ten changed
files, or at least one hundred recursively affected files.

### moderate

A change includes at least three changed files or at least ten
recursively affected files.

### low

No above threshold is detected.

Risk levels are static heuristics. A low-risk result is not a safety
guarantee and does not authorize a merge or deployment.

## 7. Fail-Closed Conditions

Important error codes:

- AIOS_IMPACT_PATH_INVALID
- AIOS_IMPACT_INDEX_INVALID
- AIOS_IMPACT_INDEX_STALE
- AIOS_IMPACT_INDEX_FILESET_MISMATCH
- AIOS_IMPACT_INDEX_GRAPH_MISMATCH
- AIOS_IMPACT_GRAPH_INVALID
- AIOS_IMPACT_CHANGED_FILES_REQUIRED
- AIOS_IMPACT_CHANGED_FILE_LIMIT
- AIOS_IMPACT_CHANGED_FILE_NOT_TRACKED
- AIOS_IMPACT_AFFECTED_FILE_LIMIT
- AIOS_IMPACT_USAGE
- AIOS_IMPACT_FAILED

C170.1 errors are propagated when repository inspection fails.

No partial impact report is returned when repository truth cannot
be established.

## 8. Resource Limits

| Resource | Limit |
| --- | ---: |
| Changed files | 100 |
| Affected files | 5,000 |
| Test candidates per changed file | 200 |

Exceeding a limit fails the operation.

The analyzer does not silently truncate the impact graph.

## 9. Limitations

C170.2 currently analyzes static TypeScript dependencies.

It does not guarantee discovery of:

- Computed dynamic imports.
- Computed require paths.
- Runtime reflection.
- Framework-specific implicit dependencies.
- Non-TypeScript runtime dependencies.
- Deleted files.
- Untracked proposed files.
- Complete test coverage.

Deleted and untracked proposed files require a future Git-diff-based
analysis interface.

Test candidate discovery remains heuristic.

## 10. Commands

Run from the repository root.

Analyze one file:

```bash
node scripts/aios-dependency-impact.mjs analyze lib/example.ts
```

Analyze multiple files:

```bash
node scripts/aios-dependency-impact.mjs analyze lib/a.ts lib/b.ts
```

Run independent tests:

```bash
node --test scripts/aios-dependency-impact.test.mjs
```

Run C170.1 and C170.2 together:

```bash
node --test scripts/aios-engineering-context.test.mjs scripts/aios-dependency-impact.test.mjs
```

1. Recursive reverse dependency discovery.

3. Multi-file aggregation and duplicate removal.
4. Likely test candidate discovery.
5. Critical package configuration risk.
6. Dirty worktree rejection.
7. Stale index rejection.
8. Untracked changed-file rejection.
9. Path traversal rejection.
10. Tampered dependency graph rejection.
11. Empty and oversized change-set rejection.

Tests must not access production data or require external credentials.

## 13. Security and Approval Boundaries

C170.2:

- Does not write source files.
- Does not modify Git state.
- Does not create branches.
- Does not create commits.
- Does not push code.
- Does not create or merge pull requests.
- Does not access production data.
- Does not invoke model providers.
- Does not execute generated code.
- Does not deploy to production.

Every result requires Founder review before being used to authorize
a code change.

## 14. Integration Boundary

C170.2 must remain independently testable.

It must not be integrated into the existing autonomous development
agent until:

1. Independent tests pass.
2. TypeScript validation passes.
3. Production build passes.
4. The same commit SHA is confirmed.
5. Founder review explicitly approves the next integration stage.
