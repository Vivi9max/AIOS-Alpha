## 3. Runtime Write Boundary

The following order is mandatory:
readGitHubFile()
↓
assertC14113AutonomousSafetyBeforeWrite()
↓
if denied → return
↓
writeGitHubFile()
The Safety Gate MUST execute before `writeGitHubFile()`.

## 4. DENY Test

Use a Founder‑authorized test request that violates an autonomous safety rule.

Examples:
- unauthorized repository;
- non‑main branch;
- unsafe path;
- protected configuration path;
- empty proposed content;
- dangerous operation;
- secret‑like content.

Expected result:
success: false
code: AUTONOMOUS_SAFETY_GATE_DENIED
Expected invariant:
`writeGitHubFile()` MUST NOT execute.

A DENY response alone is insufficient if the write still occurs.

## 5. ALLOW Test

Use a safe Founder‑authorized documentation change within:
`docs/`

Expected sequence:
AUTHORITATIVE READ
↓
SAFETY GATE = ALLOW
↓
WRITE
↓
COMMIT
Expected result must contain a real commit SHA.

## 6. READBACK Test

After successful WRITE:
`readGitHubFile()`

must execute against the same:
- repository
- branch
- path

The returned content MUST equal the requested content exactly.

Expected:
`readbackVerified: true`

## 7. Content Mismatch Test

If readback content differs from requested content:
success: false
code: READBACK_CONTENT_MISMATCH
The runtime MUST NOT report:
`VERIFIED`

## 8. Production Acceptance

C141.13 Production Verification passes only when:

- [PASS] Production build succeeds
- [PASS] Founder authorization
- [PASS] Founder Contract enforcement
- [PASS] Repository restriction
- [PASS] Branch restriction
- [PASS] Authoritative READ

- [PASS] Real commit SHA returned
- [PASS] READBACK succeeds

- [PASS] readbackVerified = true

## 9. Failure Rule

Never mark C141.13 as VERIFIED because:
- a source file exists;
- a patch exists;
- a documentation file exists;
- an API returns HTTP 200;
- a WRITE returns a commit SHA.

C141.13 is VERIFIED only after the complete runtime chain is observed.
